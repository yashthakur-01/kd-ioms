# Plan 02-01: Backend Retailer Module & Authorization Middleware

<objective>
Implement the backend retailer onboarding domain: validation schemas, database service, Express controller and routes, and the `requireApprovedRetailer` authorization middleware, verified by automated integration tests.
</objective>

<threat_model>
- **T-02-01 (Injection / Validation Bypass):** Malformed or maliciously crafted GSTIN or Drug License input bypassed to database.
  - *Mitigation:* Strict Zod validation matching `REGEX.GSTIN`, `REGEX.DRUG_LICENSE`, `REGEX.PINCODE_INDIAN`, and `REGEX.PHONE_E164`.
- **T-02-02 (Unauthorized Profile Tampering):** Retailer attempts to edit already approved drug license details.
  - *Mitigation:* `upsertMine` checks `approval_status === 'APPROVED'` and throws 409 `INVALID_STATE_TRANSITION` (per D-06).
- **T-02-03 (Admin Action Forgery / State Race):** Concurrent approve/reject requests on already processed applications.
  - *Mitigation:* Atomic SQL conditional update (`WHERE approval_status = 'PENDING'`) throwing 409 `INVALID_STATE_TRANSITION` on duplicate reviews.
- **T-02-04 (Gated Resource Access):** Unapproved retailer bypasses frontend to call catalog or ordering APIs directly.
  - *Mitigation:* `requireApprovedRetailer` middleware checks database `approval_status` and immediately returns 403 `RETAILER_NOT_APPROVED`.
</threat_model>

  <action>
    Create `backend/src/modules/retailer/retailer.validation.ts` and `backend/src/modules/retailer/retailer.service.ts`:
    1. In `retailer.validation.ts`, author Zod schemas:
       - `upsertProfileSchema`: `shopName` (2-120), `addressLine` (5-250), `city` (1-100), `state` (1-100), `pincode` (`REGEX.PINCODE_INDIAN`), `whatsappNumber` (`REGEX.PHONE_E164`), `email` (optional email or empty), `drugLicenseNumber` (5-50 trimmed), `gstin` (optional 15-char uppercase regex `REGEX.GSTIN`).
       - `listRetailersSchema`: `approvalStatus` (optional `ApprovalStatus` enum), `q` (optional string max 100), `page` (coerce number >= 1, default 1), `pageSize` (coerce number 1-100, default 20).
       - `getRetailerSchema`: `userId` (uuid).
       - `approveRetailerSchema`: `userId` (uuid).
       - `rejectRetailerSchema`: `userId` (uuid), `reason` (string 5-300 chars, trimmed per D-10).
    2. In `retailer.service.ts`, implement:
       - `getMine(userId: string)`: `SELECT * FROM retailer_profiles WHERE user_id = $1`. Returns camelized profile and `approvalStatus` (or null if unsubmitted) per FR-RET-01.
       - `upsertMine(userId: string, dto)`:
         - Queries existing row: if exists and `approval_status === 'APPROVED'`, throws `ConflictError({ code: ERROR_CODES.INVALID_STATE_TRANSITION, message: 'Approved profiles cannot be edited directly' })` per D-06, FR-RET-03.
         - Inserts or updates: `INSERT INTO retailer_profiles ... ON CONFLICT (user_id) DO UPDATE ...` resetting `approval_status = 'PENDING'`, `rejection_reason = NULL`, `updated_at = NOW()` per FR-RET-02, D-08.
         - Catches unique violation `23505`: inspects `err.constraint` or `err.detail` to pinpoint `drug_license_number` or `gstin`, throwing `ConflictError` targeting the field (`errors: [{ field: 'drugLicenseNumber', ... }]`) per D-07.
       - `listRetailers(query)`: joins `retailer_profiles` with `users` (username, phone, is_active), filtering by `approval_status` and case-insensitive search `q` on `shop_name`, `drug_license_number`, `whatsapp_number`, `username`. Returns `{ rows, totalItems }` per FR-RET-04.
       - `getRetailerById(userId: string)`: fetches retailer profile joined with user metadata. Throws `NotFoundError` if missing per FR-RET-04.
       - `reviewRetailer(adminId: string, userId: string, decision: 'APPROVE' | 'REJECT', reason?: string)`:
         - Executes atomic `UPDATE retailer_profiles SET approval_status = $1, rejection_reason = $2, reviewed_by = $3, reviewed_at = NOW(), updated_at = NOW() WHERE user_id = $4 AND approval_status = 'PENDING' RETURNING *` per D-10, D-11, FR-RET-05, FR-RET-06.
         - If zero rows updated, checks if profile exists: if exists with different status, throws `ConflictError({ code: ERROR_CODES.INVALID_STATE_TRANSITION, message: 'Only PENDING profiles can be reviewed' })`; if missing, throws `NotFoundError`.
  </action>
