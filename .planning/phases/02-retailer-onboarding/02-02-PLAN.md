# Plan 02-02: Frontend Client State, Layout Gating & Retailer Portal

<objective>
Build the frontend retailer feature module, reactive layout navigation gating, and the retailer profile KYC page supporting all state variations (unsubmitted, pending, rejected, approved).
</objective>

<threat_model>
- **T-02-05 (UI State Drift / Desynchronization):** Retailer remains locked out after admin approval or bypasses navigation locks without approval.
  - *Mitigation:* `useRetailerProfile` hook provides single source of truth; tab refocus and on-demand "Check Status" button trigger immediate cache refresh (per D-13, D-14, D-15).
- **T-02-06 (Accidental Form Re-submission):** User double-clicks submit or submits while already under review.
  - *Mitigation:* Immediate UI flip to read-only inspector upon submission (per D-08); submit button shows active spinner and disables during mutation.
</threat_model>

  <action>
    Create the retailer feature module under `frontend/src/features/retailer/`:
    1. In `keys.ts`, export `retailerKeys`:
       - `all: ['retailers'] as const`
       - `me: () => [...retailerKeys.all, 'me'] as const`
       - `list: (params?: Record<string, any>) => [...retailerKeys.all, 'list', params] as const`
       - `detail: (userId: string) => [...retailerKeys.all, 'detail', userId] as const`
    2. In `schema.ts`, author Zod validation matching backend:
       - `retailerProfileFormSchema`: `shopName` (2-120), `addressLine` (5-250), `city` (1-100), `state` (1-100), `pincode` (6 digits), `whatsappNumber` (E.164), `email` (optional/empty), `drugLicenseNumber` (5-50 trimmed), `gstin` (optional 15-char uppercase).
       - Export types `RetailerProfileFormData`, `RetailerProfileResponse`.
    3. In `api.ts`, implement API client calls:
       - `fetchMyProfile()`: calls `GET /api/v1/retailers/me`.
       - `upsertMyProfile(dto)`: calls `PUT /api/v1/retailers/me`.
       - `fetchRetailers(params)`: calls `GET /api/v1/retailers`.
       - `fetchRetailerById(userId)`: calls `GET /api/v1/retailers/${userId}`.
       - `approveRetailer(userId)`: calls `POST /api/v1/retailers/${userId}/approve`.
       - `rejectRetailer(userId, reason)`: calls `POST /api/v1/retailers/${userId}/reject`.
    4. In `hooks.ts`, implement React Query hooks:
       - `useRetailerProfile()`: query on `retailerKeys.me()`, with `refetchOnWindowFocus: true` per D-13. Returns `{ profile, approvalStatus, isApproved, isPending, isRejected, isUnsubmitted, isLoading, refetch }` per D-15.
       - `useUpsertProfile()`: mutation with invalidation of `retailerKeys.me()`.
       - `useRetailers(params)`: query on `retailerKeys.list(params)`.
       - `useRetailerDetail(userId)`: query on `retailerKeys.detail(userId)`.
       - `useApproveRetailer()`: mutation with invalidation of `retailerKeys.list()` and `retailerKeys.detail()`.
       - `useRejectRetailer()`: mutation with invalidation of `retailerKeys.list()` and `retailerKeys.detail()`.
  </action>
  <acceptance_criteria>

    - `frontend/src/features/retailer/hooks.ts` exports `useRetailerProfile` with `refetchOnWindowFocus: true`.
  </acceptance_criteria>
