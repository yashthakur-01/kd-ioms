## 2. Tasks & Detailed Instructions

### Task 1: Complete Operational Lifecycle Walkthrough
1. Create end-to-end verification script or test `backend/src/modules/alert/__tests__/phase10.lifecycle.test.ts`:
   - **Step 1: Settings & Cache Check**
     - Fetch initial settings (`GET /api/v1/settings`) -> assert `expiryAlertDays === 60`.
     - Update threshold to `90` days (`PATCH /api/v1/settings`) -> assert in-memory cache evicted and returns `90`.
   - **Step 2: Dynamic Alert Ingestion**
     - Seed Batch A with expiry in 75 days.
     - With `expiry_alert_days = 90`, Batch A appears in `GET /api/v1/alerts/near-expiry`.
     - Update threshold to `30` days -> Batch A disappears immediately from `GET /api/v1/alerts/near-expiry`.
     - Restore threshold to `90` days -> Batch A reappears.
   - **Step 3: Alert Dismissal**
     - Call `POST /api/v1/alerts/near-expiry/:batchId/dismiss` for Batch A.
     - Verify Batch A is now excluded from `GET /api/v1/alerts/near-expiry`.
   - **Step 4: Expiration & Physical Write-Off**
     - Seed Batch B with expiry in the past (`expiry_date < today_ist()`) and `quantity_on_hand = 50`.
     - Attempt dismissal on Batch B -> assert rejected with 409 `INVALID_STATE_TRANSITION`.
     - Verify Batch B appears in `GET /api/v1/alerts/expired`.
     - Attempt `POST /api/v1/batches/:batchId/remove-expired` on Batch A (unexpired) -> assert rejected with 409 `INVALID_STATE_TRANSITION`.
     - Execute `POST /api/v1/batches/:batchId/remove-expired` on Batch B with reason "Disposed in bio-waste bin".
     - Assert response confirms full quantity removed and balance is 0.
     - Assert row written to `stock_ledger_entries` with `entry_type = 'EXPIRY_WRITEOFF'`, `delta = -50`, and matching reason.
     - Assert Batch B disappears from `GET /api/v1/alerts/expired`.
   - **Step 5: Dashboard Reconciliation**
     - Call `GET /api/v1/dashboard/summary`.
     - Assert `nearExpiryBatches`, `expiredBatches`, and other operational counts reconcile 100% with underlying table totals.
