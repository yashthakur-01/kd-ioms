# Plan 10-05: Frontend Settings & Executive Dashboard

**Phase:** Phase 10 — Expiry Alerts, Settings and Dashboard  
**Plan ID:** `10-05`  
**Wave:** 5  
**Dependencies:** Plan 10-01 (Settings API), Plan 10-03 (Dashboard API), Plan 10-04 (Alerts UI)  
**Responsible Developer:** `dev3`  

---

## 1. Objective

Deliver the complete frontend administrative settings management experience (`/settings`) and replace the Phase 0 dashboard placeholder with a real-time executive operations hub (`/dashboard`) featuring 8 interactive metric tiles, deep links to operational queues, and quick administrative shortcuts.

---

## 2. Tasks & Detailed Instructions

### Task 1: Settings Feature Module (`frontend/src/features/settings/`)
1. Create `frontend/src/features/settings/types.ts`:
   - Data contracts for `AppSettings`, `BusinessProfile`, `PatchSettingsInput`.
2. Create `frontend/src/features/settings/schema.ts`:
   - Client-side Zod validation matching backend constraints:
     - `expiryAlertDays`: 1 to 730 days.
     - `businessProfile.gstin`: Valid Indian GSTIN format.
     - `businessProfile.phone`: Standard phone regex.
     - `businessProfile.email`: Standard email validation.
3. Create `frontend/src/features/settings/api.ts`:
   - `fetchSettings()` -> `GET /api/v1/settings`
   - `updateSettings(data)` -> `PATCH /api/v1/settings`
4. Create `frontend/src/features/settings/hooks.ts`:
   - `useSettings()`: React Query query hook.
   - `useUpdateSettingsMutation()`: On success, invalidates `['settings']`, `['alerts', 'near-expiry']`, and `['dashboard', 'summary']`.
5. Create `frontend/src/features/settings/components/SettingsForm.tsx`:
   - Card 1: **Warehouse Operations & Alerts**
     - Expiry Alert Window stepper (1–730 days). Helper text: "Batches with expiry dates within this threshold will trigger warehouse alerts."
   - Card 2: **Business & Invoicing Profile**
     - Company Legal Name, Registered Address, GSTIN, Drug License Number, Support Phone, Official Email.
   - Submit button with pending state, dirty check, and toast notification.
6. Create `frontend/src/app/(admin)/settings/page.tsx`:
   - Render page header with title "Global System Settings" and subtitle.
   - Mount `SettingsForm`.

### Task 2: Dashboard Feature Module (`frontend/src/features/dashboard/`)
1. Create `frontend/src/features/dashboard/types.ts`:
   - Interface `DashboardSummaryData`.
2. Create `frontend/src/features/dashboard/api.ts`:
   - `fetchDashboardSummary()` -> `GET /api/v1/dashboard/summary`
3. Create `frontend/src/features/dashboard/hooks.ts`:
   - `useDashboardSummary()`: Polls with 30-second refetch or manual refresh trigger.
4. Create `frontend/src/features/dashboard/components/DashboardSummaryCards.tsx`:
   - 8 interactive KPI cards arranged in an auto-fitting responsive grid:
     1. **Pending Retailers:** Count, link -> `/retailers?status=PENDING`
     2. **Placed Orders:** Count, link -> `/orders?status=PLACED`
     3. **Approved Unclaimed:** Count, link -> `/orders?status=APPROVED`
     4. **Out for Delivery:** Count, link -> `/orders?status=DISPATCHED`
     5. **Near Expiry Batches:** Warning badge, link -> `/alerts?tab=near-expiry`
     6. **Expired Batches:** Destructive badge, link -> `/alerts?tab=expired`
     7. **Out of Stock:** Destructive badge, link -> `/alerts?tab=out-of-stock`
     8. **Failed Notifications:** Alert badge, link -> `/notifications?status=FAILED`
   - Features: Clean glassmorphic borders, hover lift micro-animations, skeleton loaders.
5. Create `frontend/src/features/dashboard/components/QuickActions.tsx`:
   - Direct button links for daily admin workflows:
     - "Inward New Stock" -> `/stock/inward`
     - "Review Retailers" -> `/retailers`
     - "Check Expiry Alerts" -> `/alerts`
     - "System Settings" -> `/settings`
6. Update `frontend/src/app/(admin)/dashboard/page.tsx`:
   - Replace the static Phase 0 placeholder with `DashboardSummaryCards` and `QuickActions`.
   - Add refresh button to trigger instantaneous refetch.

### Task 3: Automated Frontend Tests
1. Create `frontend/src/features/settings/__tests__/settings.test.tsx`:
   - Verify initial settings load and populate form inputs.
   - Test invalid GSTIN triggers client-side validation error.
   - Test submitting valid form fires update mutation.
2. Create `frontend/src/features/dashboard/__tests__/dashboard.test.tsx`:
   - Verify summary cards render with API-provided figures.
   - Verify card click navigation targets correspond to exact queue query params.
