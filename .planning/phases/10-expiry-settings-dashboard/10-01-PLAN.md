# Plan 10-01: Settings Module & In-Memory TTL Cache

**Phase:** Phase 10 — Expiry Alerts, Settings and Dashboard  
**Plan ID:** `10-01`  
**Wave:** 1  
**Dependencies:** Phase 0 (Database, AppError, Config), Phase 1 (Auth Middleware)  
**Responsible Developer:** `dev3`  

---

## 1. Objective

Implement administrative system configuration management (`GET /api/v1/settings` and `PATCH /api/v1/settings`) operating against `app_settings` with an in-memory 60-second TTL cache, automatic invalidation on updates, and strict validation for Indian business credentials (GSTIN, Drug License).

---

## 2. Tasks & Detailed Instructions

### Task 1: Validation Schemas (`backend/src/modules/settings/settings.validation.ts`)
1. Create `backend/src/modules/settings/settings.validation.ts`:
   - Define `patchSettingsSchema`:
     ```ts
     import { z } from 'zod';

     export const patchSettingsSchema = z.object({
       body: z.object({
         expiryAlertDays: z
           .number()
           .int('Expiry alert days must be an integer')
           .min(1, 'Expiry alert days must be at least 1')
           .max(730, 'Expiry alert days cannot exceed 730')
           .optional(),
         businessProfile: z
           .object({
             name: z.string().trim().min(1).max(200).optional(),
             address: z.string().trim().min(1).max(500).optional(),
             gstin: z
               .string()
               .trim()
               .regex(
                 /^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}$/,
                 'Invalid Indian GSTIN format'
               )
               .optional(),
             drugLicenseNumber: z.string().trim().min(1).max(100).optional(),
             phone: z
               .string()
               .trim()
               .regex(/^\+?[1-9]\d{1,14}$/, 'Invalid phone number format')
               .optional(),
             email: z.string().trim().email('Invalid email address').optional(),
             logoPath: z.string().trim().nullable().optional(),
           })
           .optional(),
       }),
     });
     ```

### Task 2: Settings Service & In-Memory Cache (`backend/src/modules/settings/settings.service.ts`)
1. Create `backend/src/modules/settings/settings.service.ts`:
   - Declare interfaces:
     ```ts
     export interface BusinessProfile {
       name: string;
       address: string;
       gstin: string;
       drugLicenseNumber: string;
       phone: string;
       email: string;
       logoPath?: string | null;
     }

     export interface AppSettingsResponse {
       expiryAlertDays: number;
       businessProfile: BusinessProfile;
     }

     export interface PatchSettingsDto {
       expiryAlertDays?: number;
       businessProfile?: Partial<BusinessProfile>;
     }
     ```
   - In-memory cache implementation:
     - `let settingsCache: { data: AppSettingsResponse; cachedAt: number } | null = null;`
     - `const CACHE_TTL_MS = 60 * 1000; // 60 seconds`
     - `export function invalidateSettingsCache(): void { settingsCache = null; }`
   - `getSettings(): Promise<AppSettingsResponse>`:
     - If `settingsCache && (Date.now() - settingsCache.cachedAt < CACHE_TTL_MS)`, return `settingsCache.data`.
     - Query `app_settings` for `key IN ('expiry_alert_days', 'business_profile')`.
     - Parse JSON values. Fallback to default constants if rows are missing.
     - Save to `settingsCache` with `cachedAt: Date.now()`.
     - Return the parsed response.
   - `updateSettings(dto: PatchSettingsDto, userId: string): Promise<AppSettingsResponse>`:
     - Acquire database client and execute inside a transaction.
     - If `dto.expiryAlertDays !== undefined`:
       - `UPDATE app_settings SET value = jsonb_build_object('days', $1::int), updated_by = $2, updated_at = NOW() WHERE key = 'expiry_alert_days'`
     - If `dto.businessProfile !== undefined`:
       - Read current `business_profile` JSON with `FOR UPDATE`.
       - Shallow-merge existing keys with incoming non-undefined properties.
       - `UPDATE app_settings SET value = $1::jsonb, updated_by = $2, updated_at = NOW() WHERE key = 'business_profile'`
     - Commit transaction.
     - Invalidate memory cache (`invalidateSettingsCache()`).
     - Query and return fresh settings.

### Task 3: Controller, Routes & Registration
1. Create `backend/src/modules/settings/settings.controller.ts`:
   - `handleGetSettings(req, res)`: Invokes `getSettings()`, returns standardized success envelope `{ success: true, data: settings }`.
   - `handlePatchSettings(req, res)`: Invokes `updateSettings(req.body, req.user.id)`, returns `{ success: true, message: 'Settings updated successfully', data: settings }`.
2. Create `backend/src/modules/settings/settings.route.ts`:
   - Apply middleware: `authenticate`, `authorize(USER_ROLE.ADMIN)`, `requirePasswordChanged`.
   - `GET /` -> `asyncHandler(handleGetSettings)`
   - `PATCH /` -> `validate(patchSettingsSchema)`, `asyncHandler(handlePatchSettings)`
3. Register in `backend/src/routes/index.ts`:
   - Mount `router.use('/settings', settingsRouter);`.

### Task 4: Integration Test Suite (`backend/src/modules/settings/__tests__/settings.integration.test.ts`)
1. Create integration test suite:
   - `GET /api/v1/settings` requires Admin authorization (returns 401 for unauthenticated, 403 for non-admin).
   - `GET /api/v1/settings` returns default settings payload (`expiryAlertDays: 60`, valid `businessProfile`).
   - In-memory cache behavior: multiple calls within 60s return identical payload without reloading from DB.
   - `PATCH /api/v1/settings` modifies `expiryAlertDays`, purges cache, and returns new value on subsequent GET.
   - `PATCH /api/v1/settings` validates invalid inputs:
     - Reject negative days or days > 730 with 400 `VALIDATION_ERROR`.
     - Reject malformed GSTIN (e.g. `123INVALID`) with 400 `VALIDATION_ERROR`.
     - Reject invalid email or phone number.
   - Partial updates: updating only `businessProfile.phone` preserves company name, address, and GSTIN.
