# Plan 10-03: Dashboard Summary API

**Phase:** Phase 10 — Expiry Alerts, Settings and Dashboard  
**Plan ID:** `10-03`  
**Wave:** 3  
**Dependencies:** Phase 0 (Init DB & Views), Phase 1 (Auth), Plan 10-01 (Settings), Plan 10-02 (Alerts)

## 1. Objective

Implement high-throughput operational dashboard summary endpoint `GET /api/v1/dashboard/summary` executing 8 non-blocking, concurrent count queries via `Promise.all` across PostgreSQL pool connections, returning reconciled counts across all critical operational queues.

---

## 2. Tasks & Detailed Instructions

### Task 1: Dashboard Service (`backend/src/modules/dashboard/dashboard.service.ts`)
1. Create `backend/src/modules/dashboard/dashboard.service.ts`:
   - Declare response interface:
     ```ts
     export interface DashboardSummaryResponse {
       pendingRetailers: number;
       placedOrders: number;
       approvedUnclaimed: number;
       outForDelivery: number;
       nearExpiryBatches: number;
       expiredBatches: number;
       outOfStockMedicines: number;
       failedNotifications: number;
     }
     ```
   - Implement `getDashboardSummary(): Promise<DashboardSummaryResponse>`:
     - Run 8 parallel queries via `Promise.all([ ... ])`:
       ```ts
       const [
         pendingRetailersRes,
         placedOrdersRes,
         approvedUnclaimedRes,
         outForDeliveryRes,
         nearExpiryBatchesRes,
         expiredBatchesRes,
         outOfStockMedicinesRes,
         failedNotificationsRes,
       ] = await Promise.all([
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM retailers
           WHERE verification_status = 'PENDING'
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM orders
           WHERE status = 'PLACED'
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM orders
           WHERE status = 'APPROVED' AND claimed_by IS NULL
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM orders
           WHERE status = 'DISPATCHED'
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM v_expiry_alerts
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM v_expired_stock
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM v_medicine_availability
           WHERE available_qty = 0
         `),
         pool.query<{ count: number }>(`
           SELECT COUNT(*)::int AS count
           FROM notification_logs
           WHERE status = 'FAILED'
         `),
       ]);
       ```
     - Return mapped counts:
       ```ts
       return {
         pendingRetailers: pendingRetailersRes.rows[0]?.count ?? 0,
         placedOrders: placedOrdersRes.rows[0]?.count ?? 0,
         approvedUnclaimed: approvedUnclaimedRes.rows[0]?.count ?? 0,
         outForDelivery: outForDeliveryRes.rows[0]?.count ?? 0,
         nearExpiryBatches: nearExpiryBatchesRes.rows[0]?.count ?? 0,
         expiredBatches: expiredBatchesRes.rows[0]?.count ?? 0,
         outOfStockMedicines: outOfStockMedicinesRes.rows[0]?.count ?? 0,
         failedNotifications: failedNotificationsRes.rows[0]?.count ?? 0,
       };
       ```

### Task 2: Controller, Route & Registration
1. Create `backend/src/modules/dashboard/dashboard.controller.ts`:
   - `handleGetDashboardSummary(req, res)`:
     - Calls `getDashboardSummary()`.
     - Returns `{ success: true, data: summary }`.
2. Create `backend/src/modules/dashboard/dashboard.route.ts`:
   - Apply middleware: `authenticate`, `authorize(USER_ROLE.ADMIN)`, `requirePasswordChanged`.
   - `GET /summary` -> `asyncHandler(handleGetDashboardSummary)`.
3. Register in `backend/src/routes/index.ts`:
   - Mount `router.use('/dashboard', dashboardRouter);`.

### Task 3: Integration Test Suite (`backend/src/modules/dashboard/__tests__/dashboard.integration.test.ts`)
1. Create integration tests:
   - Authorization gates: unauthenticated returns 401, non-admin (e.g. RETAILER, PICKER) returns 403.
   - Initial count check: on baseline database, returns integer zero or initial seed counts.
   - Seed test:
     - Insert 2 pending retailers -> verify `pendingRetailers === 2`.
     - Seed 1 near-expiry batch and 1 expired batch -> verify `nearExpiryBatches` and `expiredBatches` reconcile 100%.
     - Seed 1 failed notification log -> verify `failedNotifications === 1`.
   - Concurrency check: Ensure endpoint handles burst traffic without pool exhaustion.
