**Dependencies:** Plan 10-01 (Settings Module), Phase 4 (Stock Ledger & Batches)  
**Responsible Developer:** `dev3`

## 1. Objective

Implement the operational alerting and disposal APIs:
1. `GET /api/v1/alerts/near-expiry` and `GET /api/v1/alerts/expired` using pre-compiled database views `v_expiry_alerts` and `v_expired_stock`.
2. `POST /api/v1/alerts/near-expiry/:batchId/dismiss` to record administrative dismissal ("keep as it is") while retaining post-expiry visibility.
3. `POST /api/v1/batches/:batchId/remove-expired` to execute physical removal from shelves via `applyLedgerEntry(EXPIRY_WRITEOFF)`.

### Task 2: Alert Service (`backend/src/modules/alert/alert.service.ts`)
1. Create `backend/src/modules/alert/alert.service.ts`:
   - `listNearExpiry({ page, pageSize, search })`:
     - Query `v_expiry_alerts`:
       ```sql
       SELECT batch_id, medicine_id, medicine_name, batch_number, expiry_date,
              days_left, quantity_on_hand, mrp, selling_price,
              COUNT(*) OVER() AS full_count
       FROM v_expiry_alerts
       WHERE ($1::text IS NULL OR medicine_name ILIKE ('%' || $1 || '%') OR batch_number ILIKE ('%' || $1 || '%'))
       ORDER BY days_left ASC, medicine_name ASC
       LIMIT $2 OFFSET $3
       ```
     - Return `{ items, meta: { page, pageSize, total, totalPages } }`.
   - `listExpired({ page, pageSize, search })`:
     - Query `v_expired_stock`:
       ```sql
       SELECT batch_id, medicine_id, medicine_name, batch_number, expiry_date,
              days_expired, quantity_on_hand, mrp, selling_price,
              COUNT(*) OVER() AS full_count
       FROM v_expired_stock
       WHERE ($1::text IS NULL OR medicine_name ILIKE ('%' || $1 || '%') OR batch_number ILIKE ('%' || $1 || '%'))
       ORDER BY days_expired DESC, medicine_name ASC
       LIMIT $2 OFFSET $3
       ```
     - Return `{ items, meta: { page, pageSize, total, totalPages } }`.
   - `dismissNearExpiryAlert(batchId: number)`:
     - Check batch existence and state:
       ```sql
       SELECT batch_id, expiry_date, (expiry_date < today_ist()) AS is_expired
       FROM batches WHERE batch_id = $1
       ```
     - If not found -> throw `NotFoundError('Batch not found')`.
     - If `is_expired` -> throw `BusinessRuleError({ code: 'INVALID_STATE_TRANSITION', httpStatus: 409, message: 'Cannot dismiss an alert for an already expired batch' })`.
     - Update dismissal timestamp:
       ```sql
       UPDATE batches
       SET expiry_alert_dismissed_at = NOW(), updated_at = NOW()
       WHERE batch_id = $1
       RETURNING batch_id, batch_number, expiry_alert_dismissed_at
       ```
     - Returns updated batch object.

### Task 3: Physical Expired Removal (`backend/src/modules/batch/batch.service.ts`)
1. Implement `removeExpiredBatch(batchId: number, adminId: string, reason?: string)` in `backend/src/modules/batch/batch.service.ts`:
   - Acquire client from `pool.connect()` and begin transaction.
   - Lock batch row in ascending order via `lockBatches(client, [batchId])`.
   - Fetch batch:
     ```sql
     SELECT batch_id, medicine_id, batch_number, expiry_date, quantity_on_hand,
            (expiry_date < today_ist()) AS is_expired
     FROM batches WHERE batch_id = $1
     ```
   - If not found -> throw `NotFoundError('Batch not found')`.
   - If `!is_expired` -> throw `BusinessRuleError({ code: 'INVALID_STATE_TRANSITION', httpStatus: 409, message: 'Cannot remove unexpired batch as expired stock' })`.
   - If `quantity_on_hand <= 0` -> throw `BusinessRuleError({ code: 'BATCH_ALREADY_EMPTY', httpStatus: 400, message: 'Batch stock is already zero' })`.
   - Execute ledger write-off:
     ```ts
     await applyLedgerEntry(client, {
       batchId,
       type: 'EXPIRY_WRITEOFF',
       delta: -batch.quantity_on_hand,
       reason: reason || 'Physical removal of expired stock from warehouse shelf',
       userId: adminId,
     });
     ```
   - Commit transaction.
   - Return `{ batchId, removedQuantity: batch.quantity_on_hand, balanceAfter: 0 }`.
