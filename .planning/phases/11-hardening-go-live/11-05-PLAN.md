## 1. Objective

Configure Playwright (`frontend/playwright.config.ts`) and implement a complete end-to-end browser automation suite (`frontend/e2e/order-lifecycle.spec.ts`) that executes the entire business workflow across all roles (`ADMIN`, `RETAILER`, `DELIVERY`): Onboard Retailer → Admin Approval → Batch Inwarding → Catalog Order Placement → FEFO Pick & Approval → Delivery Claim → Doorstep Delivery with Photo & Whole-Line Refusal → Stock Return & Invoice Verification.

---

## 2. Tasks & Detailed Instructions

### Task 1: Playwright Configuration (`frontend/playwright.config.ts`)
- Create `frontend/playwright.config.ts`:
  ```typescript
  import { defineConfig, devices } from '@playwright/test';

  export default defineConfig({
    testDir: './e2e',
    timeout: 60000,
    fullyParallel: false,
    forbidOnly: !!process.env.CI,
    retries: process.env.CI ? 2 : 0,
    workers: 1,
    reporter: 'list',
    use: {
      baseURL: process.env.PLAYWRIGHT_BASE_URL || 'http://localhost:3000',
      trace: 'on-first-retry',
      screenshot: 'only-on-failure',
    },
    projects: [
      {
        name: 'chromium',
        use: { ...devices['Desktop Chrome'] },
      },
    ],
  });
  ```
- Add npm script to root `package.json`:
  ```json
  "test:e2e": "playwright test --config=frontend/playwright.config.ts"
  ```

### Task 2: E2E Test Fixtures & Database Reset Helpers (`frontend/e2e/helpers/`)
- Implement test setup helpers:
  - `e2e/helpers/auth.ts`: Helper for logging in via UI form (`loginAsAdmin`, `loginAsRetailer`, `loginAsDelivery`).
  - `e2e/helpers/api.ts`: Direct backend API calls for deterministic seed verification.

### Task 3: Full Lifecycle Scenario Test (`frontend/e2e/order-lifecycle.spec.ts`)
- Author test scenario covering Section 17 of `tech.md`:
  1. **Step 1: Admin Seed Login**:
     - Navigate to `/login`.
     - Log in with `admin` / `Admin@KD2026!`.
     - Verify navigation to `/dashboard`.
  2. **Step 2: Retailer Registration & Admin Approval**:
     - Retailer submits registration at `/register`.
     - Admin visits `/retailers`, reviews submitted drug license, and clicks "Approve".
  3. **Step 3: Stock Inwarding**:
     - Admin navigates to `/stock/inward`.
     - Fills medicine batch form (`CRO-2026-X1`, Expiry 2027-12-31, Qty 100, MRP 50.00, Purchase Rate 30.00, Selling Price 40.00).
     - Submits and confirms inward entry.
  4. **Step 4: Retailer Ordering**:
     - Retailer logs in, visits `/catalog`.
     - Searches for medicine, adds 10 units to cart.
     - Navigates to `/orders/new` (or cart checkout) and clicks "Place Order".
     - Receives order confirmation with order ID and `PLACED` status.
  5. **Step 5: Admin Order Approval & FEFO Pick**:
     - Admin opens `/orders`, locates the placed order, and opens `/orders/[id]/pick`.
     - Verifies FEFO suggested batch displays automatically.
     - Clicks "Approve Order", confirming batch allocation and inventory deduction.
  6. **Step 6: Delivery Claim & Doorstep Delivery with Refusal**:
     - Delivery partner logs in, visits `/delivery/pool`.
     - Claims the order and transitions status to `OUT_FOR_DELIVERY`.
     - Opens `/delivery/orders/[id]`.
     - Marks 1 item accepted and 1 item refused (with refusal reason "Packaging damaged").
     - Attaches mock delivery proof photo.
     - Submits delivery completion.
  7. **Step 7: Verification of Invariants**:
     - Verify order status is `DELIVERED`.
     - Verify stock ledger records `RETURN_IN` for refused line item.
     - Verify invoice is generated excluding refused lines.
