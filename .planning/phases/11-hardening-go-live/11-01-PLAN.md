# Plan 11-01: Security Hardening, Helmet, Rate Limiting & OWASP Top 10 Audit

**Phase:** Phase 11 — Hardening, Reliability and Go-Live  
**Plan ID:** `11-01`  
**Wave:** 1 (Security & Protection Baseline)  
**Dependencies:** Phase 0, Phase 1, Phase 10  
**Responsible Developer:** `dev1`  

---

## 1. Objective

Harden the backend application against OWASP API Security Top 10 threats. Incorporate `helmet` for secure HTTP headers, enforce strict cookie attributes with scoped paths, add a dedicated `searchScanLimiter` (60 req/min) for search and barcode resolution endpoints, audit all routes for non-bypassable authorization, and produce an evidence-backed OWASP compliance report (`docs/OWASP-TOP-10.md`).

---

## 2. Tasks & Detailed Instructions

### Task 1: Install Helmet & Configure HTTP Security Headers (`backend/src/app.ts`)
- Install `helmet` and `@types/helmet` in `backend`:
  ```bash
  npm install helmet --workspace=backend
  npm install @types/helmet --save-dev --workspace=backend
  ```
- Update `backend/src/app.ts`:
  - Mount `helmet` before CORS and body parsers:
    ```typescript
    import helmet from 'helmet';
    // ...
    app.use(helmet({
      contentSecurityPolicy: process.env.NODE_ENV === 'production' ? undefined : false,
      crossOriginEmbedderPolicy: false,
    }));
    ```
  - Ensure CORS origin strictly reflects `env.APP_ORIGIN` with `credentials: true`.

### Task 2: Refine Sliding-Window Rate Limiters (`backend/src/middleware/rate-limit.ts`)
- Add `searchScanLimiter` with a 60-second window and 60 requests max:
  ```typescript
  // Search & Scanner Rate Limiter: 60 requests per minute
  export const searchScanLimiter = createRateLimiter({
    windowMs: 60 * 1000,
    maxRequests: 60,
  });
  ```
- Apply `searchScanLimiter` to:
  - `backend/src/modules/salt/salt.route.ts` on `/suggest`
  - `backend/src/modules/stock-inward/stock-inward.route.ts` on `/scan/resolve`
  - `backend/src/modules/batch/batch.route.ts` on `/resolve-scan`
  - `backend/src/modules/medicine/medicine.route.ts` on `GET /` when search queries are supplied

### Task 3: Scoped Cookie Security & Path Enforcement (`backend/src/modules/auth/auth.controller.ts`)
- Ensure refresh token cookie options specify:
  ```typescript
  res.cookie('refreshToken', refreshToken, {
    httpOnly: true,
    secure: env.COOKIE_SECURE,
    sameSite: env.COOKIE_SAME_SITE,
    path: '/api/v1/auth',
    maxAge: 7 * 24 * 60 * 60 * 1000,
  });
  ```
- Verify `res.clearCookie('refreshToken', { path: '/api/v1/auth' })` on logout.

### Task 4: Security Verification Test Suite (`backend/src/modules/security/__tests__/security-hardening.test.ts`)
- Implement Vitest tests with Supertest:
  1. Asserts HTTP security headers present (`x-dns-prefetch-control`, `x-frame-options`, `strict-transport-security`, etc.).
  2. Asserts CORS rejects unauthorized foreign origins.
  3. Asserts `searchScanLimiter` triggers 429 `RATE_LIMITED` after 60 requests.
  4. Asserts refresh token cookie includes `HttpOnly` and `Path=/api/v1/auth`.
  5. Asserts tenant isolation on `/orders/:orderId` and `/invoices/:invoiceId`.

### Task 5: OWASP API Security Top 10 Audit Document (`docs/OWASP-TOP-10.md`)
- Author `docs/OWASP-TOP-10.md` detailing implementation and test evidence for:
  - API1:2023 Broken Object Level Authorization (BOLA)
  - API2:2023 Broken Authentication
  - API3:2023 Broken Object Property Level Authorization
  - API4:2023 Unrestricted Resource Consumption
  - API5:2023 Broken Function Level Authorization
  - API6:2023 Unrestricted Access to Sensitive Business Flows
  - API7:2023 Server Side Request Forgery (SSRF)
  - API8:2023 Security Misconfiguration
  - API9:2023 Improper Inventory Management
  - API10:2023 Unsafe Consumption of APIs
