# Plan 11-02: Database Performance Profiling & Query Optimization

**Phase:** Phase 11 — Hardening, Reliability and Go-Live  
**Plan ID:** `11-02`  
**Wave:** 2 (Database Performance & Index Verification)  
**Dependencies:** Phase 0, Phase 4, Phase 5, Phase 7  
**Responsible Developer:** `dev1`  

---

## 1. Objective

Profile critical database queries using `EXPLAIN (ANALYZE, BUFFERS)` to guarantee that production workloads stay within target latency budgets: catalog queries under 300ms p95, and order approvals under 500ms p95. Verify that composite and GIN trigram indexes are utilized without sequential full-table scans on high-cardinality tables (`medicines`, `batches`, `stock_ledger_entries`, `orders`).

---

## 2. Tasks & Detailed Instructions

### Task 1: Query Profiling Harness (`backend/src/scripts/profile-queries.ts`)
- Implement a script that connects to the database pool and profiles core domain queries using `EXPLAIN (ANALYZE, BUFFERS)`:
  1. **Dynamic Catalog View Query**:
     ```sql
     EXPLAIN (ANALYZE, BUFFERS)
     SELECT * FROM v_catalog
     WHERE in_stock = true
       AND (name ILIKE '%paracetamol%' OR salts_text ILIKE '%paracetamol%')
     ORDER BY name ASC
     LIMIT 20 OFFSET 0;
     ```
  2. **Order Listing with Tenant Isolation**:
     ```sql
     EXPLAIN (ANALYZE, BUFFERS)
     SELECT o.*, r.pharmacy_name
     FROM orders o
     JOIN retailers r ON o.retailer_id = r.retailer_id
     WHERE o.status = 'PLACED'
     ORDER BY o.created_at DESC
     LIMIT 50;
     ```
  3. **FEFO Pick Suggestion Query**:
     ```sql
     EXPLAIN (ANALYZE, BUFFERS)
     SELECT b.*
     FROM batches b
     WHERE b.medicine_id = $1
       AND b.status = 'ACTIVE'
       AND b.expiry_date >= CURRENT_DATE
       AND b.quantity_on_hand > 0
     ORDER BY b.expiry_date ASC, b.batch_id ASC;
     ```
  4. **Stock Ledger Audit History**:
     ```sql
     EXPLAIN (ANALYZE, BUFFERS)
     SELECT * FROM stock_ledger_entries
     WHERE batch_id = $1
     ORDER BY created_at DESC
     LIMIT 100;
     ```
- Parse and display:
  - Total Planning Time
  - Total Execution Time
  - Shared Hit Blocks vs Read Blocks
  - Index Scan vs Seq Scan node types

### Task 2: Verify Index Coverage & Execution Paths
- Inspect query plans to confirm:
  - `idx_batches_sellable` on `batches(medicine_id, status, expiry_date, quantity_on_hand)` is invoked for FEFO allocations and availability.
  - Trigram GIN indexes (`idx_medicines_name_trgm`, `idx_salts_name_trgm`) are utilized for catalog autocomplete and search.
  - `idx_orders_status_retailer` is used on order filtering.
- If sequential scans or high buffer reads are detected on foreign keys, add appropriate index migrations (e.g. `006_performance_indexes.sql`).

### Task 3: Profiling Test Suite (`backend/src/scripts/__tests__/query-performance.test.ts`)
- Implement Vitest tests validating that:
  1. The profiling script executes without syntax or plan errors.
  2. Execution planning times on test datasets remain under 100ms.
  3. No unindexed sequential scan appears in catalog or batch allocation plans.

### Task 4: Documentation Report (`docs/PERFORMANCE-PROFILING.md`)
- Author `docs/PERFORMANCE-PROFILING.md` documenting:
  - Target latency SLAs (Catalog < 300ms, Approval < 500ms).
  - Exact `EXPLAIN ANALYZE` raw output and tree diagrams.
  - Index mapping and cache hit ratio recommendations for production PostgreSQL.
