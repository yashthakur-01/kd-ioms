## 1. Objective

Produce the canonical OpenAPI 3.0 specification (`docs/openapi.yaml`), author user-facing operations manuals (`docs/ADMIN-GUIDE.md`, `docs/DELIVERY-GUIDE.md`), create the comprehensive production operations and disaster recovery runbook (`docs/RUNBOOK.md`), and execute full-regression verification across all suites for Phase 11 milestone sign-off.

---

## 2. Tasks & Detailed Instructions

### Task 1: Canonical OpenAPI 3.0 YAML Specification (`docs/openapi.yaml`)
- Author comprehensive OpenAPI 3.0.3 specification covering:
  - Base URL `/api/v1`
  - Authentication scheme: `bearerAuth` (JWT) and `cookieAuth` (`refreshToken`)
  - All 14 modules: `auth`, `users`, `salts`, `medicines`, `stock`, `batches`, `retailers`, `catalog`, `orders`, `allocation`, `delivery`, `invoices`, `alerts`, `settings`, `dashboard`
  - Request bodies, Zod schemas, HTTP parameters, query strings
  - Standard envelopes (`ok`, `created`, `okList`, `fail`) and error status codes (400, 401, 403, 404, 409, 422, 429, 500)

### Task 2: Administrator Operations Manual (`docs/ADMIN-GUIDE.md`)
- Author practical guide for wholesale administrators covering:
  1. Setting up system configuration (`/settings`): business profile, GSTIN, licence, and expiry alert days.
  2. Master catalog management: adding chemical salts, registering medicines, and updating MRP/rates.
  3. Processing supplier stock inwarding via GS1 barcode scanning or manual batch entry.
  4. Reviewing incoming orders, evaluating FEFO pick suggestions, scan-to-pick workflows, and approving/rejecting orders.
  5. Managing delivery dispatch pool and handling customer service issues.
  6. Reviewing inventory alerts (near-expiry and out-of-stock) and performing expired batch disposal write-offs.

### Task 3: Delivery Partner Operations Manual (`docs/DELIVERY-GUIDE.md`)
- Author mobile/web guide for delivery staff:
  1. Logging in and rotating initial password.
  2. Accessing the Dispatch Pool (`/delivery/pool`) and claiming approved deliveries.
  3. Managing assigned deliveries (`/delivery/orders`) and navigating to retail pharmacy locations.
  4. Conducting doorstep verification: reviewing line items with pharmacy staff.
  5. Handling whole-line refusals: entering mandatory refusal reasons.
  6. Capturing photo proof of delivery or recipient confirmation.
  7. Placing on-behalf orders for retailers while visiting pharmacies.

### Task 4: Production Runbook & Release Checklist (`docs/RUNBOOK.md`)
- Author operational runbook containing:
  1. **Deployment Architecture**: Render backend, Vercel frontend, Supabase PostgreSQL & Storage.
  2. **Production Secrets Management**: Generating and rotating `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `COOKIE_SECRET`.
  3. **Database Maintenance**: Running migrations (`npm run db:migrate`), executing backups (`npm run backup`), and restore testing.
  4. **Render Free-Tier Keep-Warm**: Configuring uptime ping monitors on `/api/v1/health`.
  5. **Troubleshooting Guide**: Diagnosing pool exhaustion, deadlock retries, rate-limit thresholds, and notification delivery failures.
  6. **Signed Go-Live Checklist**: Verification sign-off criteria before serving live pharmaceutical orders.

### Task 5: Final Full-Regression Verification Run
- Execute the complete repository verification pipeline:
  ```bash
  # 1. Verify enum synchronization between workspaces
  npm run sync-enums:check
  
  # 2. Typecheck backend and lint frontend
  npm run lint
  
  # 3. Run full Vitest suite (all backend and frontend unit/integration tests)
  npm run test
  
  # 4. Compile production bundles
  npm run build
  ```
- Confirm 0 errors, 0 warnings, and 100% test pass rate across the monorepo.
